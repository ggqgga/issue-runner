production 배포 후 UI 회귀를 Chrome 스모크로 대조하라. 배포 이슈 본문의 검증 항목을
한 건씩 chrome-devtools MCP 로 production 을 직접 구동해 통과·실패를 판정한다.

**구동 절차** — chrome-devtools MCP 도구를 ToolSearch 로 로드한 뒤:
0. **진입 정리(멱등 — 크래시 재개 방어):** `list_pages` 로 이전 틱이 정리 전에 죽어
   남긴 스모크 페이지가 있으면 `close_page` 로 먼저 닫는다.
1. `navigate_page` 로 베이스 URL `<VERIFY_URL>` 에 진입한다.
2. 아래 검증 항목 각각에 대해 `take_snapshot`/`evaluate_script` 로 화면을 대조해
   항목별 pass/fail 을 산출한다. 항목이 산문("상단 인프라 탭 → /infra 렌더")이면
   LLM 해석으로 대상 경로/요소를 정하고 실제 렌더를 확인한다. **단 전 항목에 pass/fail 을
   찍는 게 아니다** — 아래 「보류(held)」 절의 두 부류는 밟지 말거나 밟지 못한 줄이라
   `보류` 로 적고 분모에서 뺀다.
3. 데이터 0 화면은 빈 상태까지만 실증 가능 — 결과에 "구조/빈 상태 확인"과
   "실 데이터 렌더 확인"을 구분 표기한다.
4. **정리(공통 종료 — 누수 방지):** 판정 산출 후, 이 스모크가 연 페이지를 `close_page`
   로 반드시 닫는다(pass·fail 어느 경로든 예외 없이). 프로덕션 페이지엔 클라이언트
   폴러가 살아 있어 좌존 탭이 CPU 를 스핀하며 누적된다 — 남기지 마라. 브라우저를 아예
   안 열었으면(degrade) 정리 대상 없음(단 도달 불가 판정용 `navigate_page` 로 에러 탭이
   열렸으면 그 탭도 close 한다).

**저하(degrade) — 조용한 skip 금지.** chrome-devtools MCP 도구가 세션에 없거나
(헤드리스/크론 환경) `<VERIFY_URL>` 이 도달 불가면, 스모크를 건너뛰고
`스모크 skip: <사유>` 로 보고한다 (누락 은폐 금지 — 사람-보고 폴백 경로로 넘긴다).

**skip 하기 전에 주소부터 의심하라.** 크롬이 `ERR_ADDRESS_UNREACHABLE` 을 내는데 같은
호스트를 `curl` 은 200 으로 받으면, 그건 서버가 죽은 게 아니라 **그 주소만 크롬에서
안 열리는 것**이다(2026-09-10 BoDAT 개발 맥북의 Chrome 실측 — 박스마다 다를 수 있다:
미니의 LAN 주소·mDNS 이름은 크롬에서만 막히고
Tailscale 주소·루프백은 정상. DNS 도 권한도 아니다). 이때는 `스모크 skip` 이 아니라
같은 박스의 다른 주소로 한 번 더 시도한다 — ① 그 레포의 원격 접근용 주소(BoDAT 은
테일넷 IP) ② SSH 터널. **둘 다 실패했을 때만** 도달 불가로 판정한다.

⚠️ **터널은 성공을 확인하고 써라 — 안 그러면 남의 서버를 프로덕션으로 판정한다.**
고정 포트를 쓰면 이미 그 포트를 물고 있는 dev 서버·다른 터널이 응답해 버리고, 스모크는
그걸 통과로 적으며 closeout 은 그 초록으로 배포 이슈를 닫는다(거짓 초록). 그래서
**포트를 매번 새로 뽑고**, `ExitOnForwardFailure=yes` 로 포워딩 실패 시 ssh 가 죽게 하고,
열자마자 한 번 찔러 확인한다:

**로컬 포트 충돌과 원격 도달 불가는 다른 것이다 — 가르는 축은 "몇 번 실패했나" 가 아니라
"어느 쪽 문제인가" 다.** 뽑은 포트를 이미 누가 물고 있으면(바인드 충돌)
`ExitOnForwardFailure=yes` 덕에 ssh 가 죽는데, 이건 **로컬 문제**다 — 바인드 실패면
**다른 포트로 재시도**하고, 5회 전부 바인드 충돌이면 전용 문자열로 갈라 보고한다(아래
`tunnel port exhausted` — **로컬 문제, 도달 불가 아님**). 반대로 ssh 가 **비-바인드
사유**(호스트 다운·인증 실패·DNS·라우팅)로 실패하면 그건 **원격/경로 문제**이므로 재시도해도
의미가 없다 — 곧장 `tunnel unreachable` 로 보고한다(새 문자열을 만들지 않는다. 바인드는 됐는데
프로브가 무응답·10초 초과인 경우와 같은 문자열로 합류시킨다 — 둘 다 원격 쪽 문제라서다).
정리는 `pkill` 이 아니라 **이 호출이 만든 control socket** 으로만 한다(같은 포트를 쓰는
남의 터널을 끊지 않게).

**control socket 경로는 변수 전달에 기대지 않는다 — 출력에 찍힌 경로를 그대로 옮겨 적는다.**
터널을 여는 스니펫과 "스모크가 끝난 뒤 정리" 스니펫은 **서로 다른 Bash 호출**이라 셸
변수(`CTL`)가 둘 사이에 살아남지 않는다. 그래서 성공 줄이
`tunnel ok on <포트>, control socket <경로>` 로 **경로 자체를 찍고**, 정리 스니펫은 그 줄에
찍힌 경로를 **문자 그대로** 옮겨 적는다(포트에서 역산하지 않는다).

⚠️ **경로에는 이 시도만의 난수를 섞는다 — `/tmp/smoke-tun-<포트>-<난수>.sock`
(`/dev/urandom` 8바이트 = 16자리 hex).** 포트만으로 경로를 정하면(`/tmp/smoke-tun-<포트>.sock`) 그 경로는 **예측 가능**해서
이 호출의 것이라는 보장이 없다: 앞 회차가 정리 전에 죽어 소켓 파일만 남았거나, 동시에 도는
다른 호출이 같은 포트를 뽑아 그 경로에 master 를 만들어 둘 수 있다. 그러면 OpenSSH 는
`ControlSocket ... already exists, disabling multiplexing` 을 찍고 **비-multiplex 로 포워딩만
성공**시키는데, 이걸 그대로 `PORT=$P; CTL=$C` 로 받으면 정리 단계의 `-O exit` 이 **남의
살아있는 master 를 끊고**, 정작 이번에 연 터널은 CTL 을 못 들고 있어 누수된다(#170).

**`-O check` 로 이걸 막으려 하지 마라 — `-O check` 는 소유를 증명하지 않는다.** 그건 "그
경로에 master 가 살아 있다"만 말하고 *누가 만들었는지는 말하지 않는다.* 사전 검사와
`ssh -M` 사이에 다른 호출이 같은 경로에 master 를 만들면, 이번 `ssh` 는 비-multiplex 로
폴백해 성공하고 그 `-O check` 는 **남의 master 에 붙어 성공**한다 — 막으려던 사고가 그대로
난다. 그래서 소유권은 검사가 아니라 **경로**로 세운다. 난수를 섞은 경로는 다른 호출이
예측해서 선점할 수 없고(맞히려면 64비트 난수를 맞혀야 한다), 덤으로 두 가지가 함께
사라진다:

- 우리 것이 아닌 경로는 **아예 건드리지 않는다** — 남의 `/tmp` 소켓을 "죽은 우리 잔재"로
  단정해 `rm -f` 할 일이 없다(`-O check` 실패는 살아있는 master 가 응답을 못 한 경우나
  같은 계정의 **다른** 소켓이 그 예측 가능한 경로에 있는 경우에도 난다).
- 경로가 신선하니 `disabling multiplexing` 폴백 자체가 일어나지 않는다.

**`$$`(셸 PID)로는 부족하다 — 측정으로 확인했다.** bash 의 `$$` 는 서브셸·파이프라인·
백그라운드 서브셸에서 전부 **부모 셸의 PID** 로 남는다(bash 3.2 실측:
`parent=72353 subshell=72353 pipeline=72353 bg-subshell=72353`). 한 셸이 이 스니펫을 두
갈래로 동시에 돌리면 두 호출의 경로가 **같아지고**, 같은 포트를 뽑는 순간(추첨 폭이 1000
이므로 드물지 않다) 바로 위의 사고가 그대로 난다 — 실제로 스텁 `ssh` 로 재현했다. `$RANDOM`
도 15비트(0–32767)에 서브셸 재시드 동작이 구현별이라 기대지 않는다. 그래서 매 시도마다
`/dev/urandom` 에서 8바이트를 읽어 쓴다(같은 셸의 네 문맥에서 전부 다른 값이 나온다).

**보장하는 것과 못 하는 것을 정확히.** 난수 경로가 보장하는 것은 *경로가 겹쳐 남의 master
를 `CTL` 로 채택하는 일이 없다*는 것까지다. 보장하지 못하는 것 — 바인드 직후 master 가
즉사하면 `-O check` 도 `-O exit` 도 붙을 곳이 없어 `ssh -f` 가 이미 띄운 포워더를 **끄지
못한다**(`pkill` 은 금지). 그 갈래에서 이 레시피가 하는 일은 **끄지 못했다는 사실을 출력에
남기는 것**뿐이다(아래 「범위 밖으로 남겨두는 것」).

**바인드 직후의 `-O check` 는 남긴다 — 다만 소유권 검사가 아니라 정상성 검사다.** 고유
경로인데 master 가 안 잡히면 남의 master 가 아니라 "우리 쪽이 뭔가 잘못됐다"는 뜻이다. 그
시도를 성공으로 치지 않되(그 소켓을 `CTL` 로 들고 가지 않는다) — `ssh -f` 가 **이미
백그라운드에 띄웠을 수 있는** 포워더를 그냥 버리지 말고 `ssh -S "$C" -O exit` 으로
**best-effort 정리**한 뒤 다음 포트로 넘어간다. 그 정리까지 실패하면 사실을 **출력에
남긴다**(`|| true` 로 삼키지 않는다 — 그 포트에 포워더가 남았을 수 있다는 유일한 단서다).
5회 다 이 갈래여도 로컬 문제이므로 바인드 충돌과 같은 `tunnel port exhausted` 로 합류한다 —
아래 세 갈래 분류는 바뀌지 않는다.

```bash
ERR=$(mktemp); PORT=""; CTL=""; ALL_BIND=1
for _try in 1 2 3 4 5; do
  P=$(( 39000 + RANDOM % 1000 ))
  U=$(od -An -N8 -tx1 /dev/urandom 2>/dev/null | tr -d ' \n')   # 이 시도만의 난수(16자리 hex)
  if [ -z "$U" ]; then
    # 난수를 못 얻으면 예측 가능한 경로로 내려가지 않는다 — 그게 이 레시피가 없애려는 결함이다.
    echo "고유 토큰 생성 실패(/dev/urandom) — 예측 가능한 경로로 진행하지 않는다"
    continue                          # 로컬 문제 → 5회 소진 시 tunnel port exhausted 로 합류
  fi
  C="/tmp/smoke-tun-$P-$U.sock"       # 포트 + 이 시도만의 난수 = 남이 예측·선점할 수 없는 경로
  if [ -e "$C" ]; then
    # 난수 경로라 사실상 안 나오는 갈래(같은 포트 + 같은 16자리 난수가 겹쳐야 한다).
    # 나더라도 우리가 만든 것이라는 보장은 없으니 지우지 말고 다시 뽑는다.
    continue
  fi
  if ssh -f -N -M -S "$C" -o ExitOnForwardFailure=yes \
       -L "127.0.0.1:$P:127.0.0.1:<원격포트>" <호스트별칭> 2>"$ERR"; then
    # 경로가 이 시도만의 난수라 여기 잡히는 master 가 남의 것일 일은 사실상 없다. 그래도 살아
    # 있는지는 확인한다 — 난수 경로에서 -O check 실패는 "남의 master" 가 아니라 "우리 쪽 이상".
    if ssh -S "$C" -O check <호스트별칭> >/dev/null 2>&1; then
      PORT=$P; CTL=$C; break          # 정상 — 이 호출이 만든 살아있는 master
    fi
    # ssh -f 가 이미 백그라운드로 포워더를 띄웠을 수 있다 — 버리지 말고 best-effort 로 끈다.
    # 그것마저 실패하면 삼키지 말고 사유를 남긴다(포트가 남았다는 유일한 단서).
    ssh -S "$C" -O exit <호스트별칭> >/dev/null 2>&1 \
      || echo "control socket 정리 실패(포트 $P 포워더가 남았을 수 있다): $C"
    continue                          # 이 시도는 성공으로 치지 않는다 — 다음 포트로
  fi
  # ExitOnForwardFailure=yes 가 바인드 실패 시 내는 stderr 는 "bind: Address already in
  # use" 류 — 이 grep 에 걸린다. 걸리지 않는(=비-바인드) 실패 예: "Could not resolve
  # hostname"(DNS) · "Connection refused"/"No route to host"(호스트 다운·라우팅) ·
  # "Permission denied"(인증 실패). 그런 실패는 포트를 바꿔 재시도해도 소용없으므로 즉시 break.
  grep -qi 'bind\|address already in use' "$ERR" || { ALL_BIND=0; break; }   # 원격/경로 문제
done
if [ -z "$PORT" ] && [ "$ALL_BIND" = 1 ]; then
  echo "tunnel port exhausted"        # 5회 전부 바인드 충돌(또는 master 미확인·토큰 실패) — 로컬 문제, 도달 불가 아님
elif [ -z "$PORT" ]; then
  echo "tunnel unreachable"           # 비-바인드 ssh 실패(호스트 다운·인증·DNS·라우팅) — 원격/경로 문제
elif curl -fsS --connect-timeout 3 --max-time 10 \
     "http://127.0.0.1:$PORT/up" -o /dev/null; then
  echo "tunnel ok on $PORT, control socket $CTL"   # ← 스모크 URL 은 http://127.0.0.1:$PORT
else
  echo "tunnel unreachable"           # 바인드는 됐지만 원격 무응답 · 응답 지연(10초 초과)
  ssh -S "$CTL" -O exit <호스트별칭> 2>/dev/null || echo "control socket 정리 실패: $CTL"
fi
rm -f "$ERR"
```

위 루프의 `-O check` 는 **이 호출이 만든 master 가 살아 있는지**만 판정한다 — 소켓이
아예 없는 것(정상 진행) 과 check 실패(우리 쪽 이상 → best-effort `-O exit` 후 다음 포트)
는 서로 다른 의미이므로 종료코드를 뭉뚱그려 `|| true` 로 삼키지 않는다. 소유권은 이 검사가
아니라 경로의 난수가 세운다.

**범위 밖으로 남겨두는 것 — `-O check` 도 `-O exit` 도 실패했을 때 이미 뜬 포워딩 프로세스
자체.** 난수 경로에서는 남의 master 를 물 일이 사실상 없으니 이 갈래에 오는 건 우리 쪽 이상(예:
master 가 즉사)뿐이다. 이때 `ssh -f` 가 이미 백그라운드로 띄운 포워더는 control socket 이
없어 `-O exit` 으로 못 끄고 `pkill` 은 금지(위 참고)라 끌 방법이 없다 — 그래서 **끄지 못한
사실을 출력에 남기는 것**까지가 계약이다(빈도가 극히 낮고 영향은 로컬 포트 하나 점유).
PID 추적으로 그 잔여 프로세스까지 끄는 건 범위 밖으로 남긴다.

**`tunnel ok` 면 터널을 열어 둔 채 크롬 스모크를 끝까지 밟는다** — 프로브 직후에 끊으면
정작 확인하려던 화면을 못 본다(확인한 건 `/up` 뿐). `CTL` 은 그 시도만의 난수가 박힌
경로라, 정리 시점의 `-O exit` 이 남의 master 에 닿으려면 다른 호출이 그 16자리 난수를
맞혀야 한다 — 그만큼 낮은 위험이지 "없다"가 아니다. 스모크가 오래 걸려 그 사이 master 가
죽었을 수도 있으므로(정상 종료·크래시 불문) 아래 `-S` 존재 확인은 그대로 남겨 둔다.
정리는 스모크가 끝난 뒤,
**통과·실패·중단 어느 경로에서든** 한 번 — 위 출력에 찍힌 **경로를 문자 그대로** 옮겨
적는다(포트에서 역산하지 않는다. 경로의 난수는 **재생성할 수 없다** — 출력에 찍힌 문자열이
유일한 출처다):

```bash
CTL="<터널 스니펫 출력의 control socket 경로>"   # 예: "tunnel ok on 39441, control socket /tmp/smoke-tun-39441-9f3c1a7b2d5e4068.sock" → /tmp/smoke-tun-39441-9f3c1a7b2d5e4068.sock
if [ -S "$CTL" ]; then
  ssh -S "$CTL" -O exit <호스트별칭> 2>/dev/null || echo "control socket 정리 실패: $CTL"
else
  echo "control socket 없음(경로 불일치 또는 이미 정리됨): $CTL"   # 조용히 넘어가지 않는다
fi
```

`tunnel unreachable` 이 찍혔을 때만 도달 불가다 — 5회 전부 바인드 충돌은 위 루프가 이미 걸러
`tunnel port exhausted` 로 따로 갈렸고(로컬 문제로 분류, skip 사유일 뿐 도달 불가 판정에 넣지
않는다), 그 외의 실패 경로 둘 — ① ssh 가 비-바인드 사유로 실패 ② 바인드는 됐지만 원격
무응답·지연(`--max-time` 이 10초에서 끊음, closeout 이 매달리지 않게) — 은 둘 다 원격/경로
쪽 문제이므로 같은 문자열로 합류한다.
정리는 control socket(`-O exit`)으로만 한다 — 포트 문자열로 넓게 `pkill` 하면 같은 포트를
쓰던 남의 터널까지 끊는다. 소켓을 못 찾으면(`-S` 실패) `|| true` 로 삼키지 말고 그 사실을
적는다. `<호스트별칭>`·`<원격포트>` 는 그 레포의 배포 절차 문서에서 찾는다(BoDAT =
`bodat-mini`(사무실 LAN)·`bodat-remote`(외부) · 3000). **통로를 못 찾으면 지어내지 말고**
`스모크 skip: 터널 통로 미상(<레포>)` 로 보고한다.

**보류(held) — 밟지 않은 줄은 pass 도 fail 도 아니다.** 아래 두 부류는 `보류` 로 적고
**분자에도 분모에도 넣지 않는다.** 크롬으로 대조한 척하면 통과든 실패든 둘 다 거짓이다.
- **접두 표식 `[칸 ③]` 이 붙은 줄** — 실장비(TEST 워커 프로필 #18 드라이런) 항목이라
  크롬이 못 밟는다. **시도조차 하지 마라.** 판별은 **표식으로만** 한다 — 줄의 뜻을 읽어
  표식 없는 줄을 실장비로 승격하거나 표식 붙은 줄을 일반 항목으로 강등하지 마라.
- **표식은 없는데 밟을 수단이 브라우저 밖에 있어 시도조차 못 한 줄** — 워커 박스·`ssh`·
  AdsPower 클라이언트 조작 · 서버 셸 `bin/rails runner` · `log/*.out` grep 처럼 프로덕션
  콘솔 화면에 없는 수단이 필요한 줄이다. 표식 없는 줄은 **일단 밟아 본다**: 밟았는데 기대와
  다른 값이 나왔으면 그건 `보류` 가 아니라 `fail` 이다(크롬이 화면·값을 실제로 봤으므로
  진짜 결함). **시도조차 못 한 것만** `보류` 다 — 근거는 줄의 뜻이 아니라 **크롬이 실제로
  밟았는지**다.

**`보류` 와 `스모크 skip:` 은 다른 말이다 — 항목별 판정에 `skip` 을 쓰지 마라.**
`스모크 skip:` 은 위 저하(degrade) 절의 **스모크 전체가 못 돈** 사유 마커다. 항목 하나를
못 밟은 것을 `skip` 으로 적으면 두 어휘가 겹쳐 소비 쪽(closeout 5단계)이 그 줄을 전체
저하로 오독하거나, 분모에 남겨 둔 채 거짓 초록을 만든다. 항목별 판정 어휘는
`pass`·`fail`·`보류` **셋뿐이다.**

**출력 계약.** 검증 항목별로 한 줄씩 `pass`/`fail`/`보류` 와 근거를 적고, 끝에
요약 `스모크: <통과수>/<전체수> 통과`(또는 `스모크 skip: <사유>`)를 낸다.
**`<전체수>` 는 크롬이 실제로 밟은 줄 수다 — `보류` 줄은 분자에도 분모에도 넣지 않는다.**
보류가 하나라도 있으면 요약 다음 줄에 내역을 낸다:
`보류 내역: 표식 <a>건 · 표식 없는 미밟음 <b>건`.
보류를 빼고 나서 밟은 줄이 0이면 `스모크: 0/0 통과` 를 내지 마라 — 그건 통과가 아니라
아무것도 안 본 것이다(거짓 초록). 요약 자리에 `스모크 생략: 밟을 항목 0` 을 내고 위
보류 내역을 함께 남긴다.
read-only — 직접 수정하지 않는다.
