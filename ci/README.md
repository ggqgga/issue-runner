# `ci/` — 로컬 CI 의 구조와 가드 은퇴 원칙

`bin/ci` 는 이제 **러너**다(13줄). 검사는 한 줄도 거기 없다.

```
bin/ci                러너 — 레포 루트로 cd 하고 ci/steps/NN-*.sh 를 이름순으로 실행
ci/steps/NN-<이름>.sh 단계 — 실제 검사. 원 bin/ci 의 실행 순서를 그대로 쪼갠 것
ci/lib.sh             단계들이 함께 쓰는 헬퍼 (source 전용)
ci/guards/<주제>.sh   흩어져 있던 문서 형태 가드를 주제별로 모은 파일 — 단계 30 이 부른다
scripts/tests/*.test.sh  행동 격자 — 단계 60 이 부른다 (판정은 전부 격자 안에 있다)
```

## 러너 계약

- 진입점은 `bin/ci` 하나다(`hooks/local-ci.sh` · `hooks/ci-gate-before-pr-merge.sh` ·
  `scripts/ci-queue.sh` 가 이 경로를 **실행 파일**로 부른다 — 실행 비트를 잃으면 앞의 두
  훅은 조용히 `exit 0` 으로 건너뛴다. 편집은 항상 제자리 덮어쓰기로, `rm` 뒤 재생성 금지).
- 단계는 `bash "$step"` 으로 부른다 — 실행 비트를 요구하지 않는다(새 단계 파일을 비트
  없이 더해도 `126` 으로 조용히 죽지 않는다). 그래서 `ci/guards/exec-bit.sh` 목록에도
  단계 파일은 넣지 않는다.
- `nullglob` 은 켜지 않는다. `ci/steps/` 가 비면 리터럴 패턴을 실행하려다 죽는다 —
  「검사 0건인데 초록」 보다 낫다(fail-closed).
- `set -euo pipefail` 은 러너와 단계 **양쪽**에 있다. 첫 비0 단계에서 그 자리 정지하고
  종료 코드를 그대로 물려준다(분할 전 인라인 `set -e` 와 같은 동작).
- 단계는 저마다 `cd "$(dirname "$0")/../.."` 를 한다 — 러너를 거치지 않고 한 단계만
  손으로 돌릴 수 있다(`bash ci/steps/60-tests.sh`).

`[N/M]` 라벨은 `10-syntax.sh`·`20-shellcheck.sh` **두 줄에만** 리터럴로 있다(`[1/12]`·
`[2/12]`). 단계 파일을 더하거나 지우면 그 두 리터럴의 `M` 을 같이 고친다. 파싱하는
소비자는 0건이다(실측) — 사람 눈금이다.

번호는 10 단위로 띄운다. 사이에 단계를 끼울 때 뒤 파일을 재번호하지 않기 위해서다.
**이름순 = 실행순**이므로 두 자리를 유지한다(`100-` 은 `20-` 앞으로 정렬된다).

## 가드 은퇴 원칙 (에픽 #398 · Plans/loop-restructure.md 4단계)

> 이 가드가 없으면 **어느 스크립트가 틀린 값을 읽는가** — 답이 없으면 CI 가 아니라
> 리뷰 몫이다.

그 기준으로 스킬·README 산문의 문구만 핀하던 검사(순수 산문 · 봇 동작 가드)를 걷어냈다.
남은 규율은 넷이다:

1. **만료 조건 없는 새 가드는 넣지 않는다.** 새 `#NNN` 가드를 더할 땐 만료 조건을 한
   줄로 함께 적어라 — 어떤 테스트 또는 SSOT(`scripts/tests/<x>.test.sh` · 값을 실제로
   읽는 스크립트 · `references/` 의 절)가 이 자리를 대신하면 지운다.
2. **만료 조건이 충족되면 지운다.** 「대체물이 생기면」 이 아니라 「대체물이 그 규칙을
   *강제*하게 되면」 이다. rationale·규약 문서는 규칙을 *설명*할 뿐 강제하지 않는다 —
   설명만으로는 은퇴 사유가 못 된다(#539 codex 1회차 재판정의 잣대).
3. **`Plans/ci-guard-classification.md` 가 블록별 만료 조건의 SSOT 다.** 단계 파일 머리
   주석은 그 표를 요약해 옮겨 적은 것이고, 판정이 갈리면 표가 이긴다.
4. **새 블록을 넣으면 그 표에 행을 더한다** — 분류(ⓐ 행동 테스트 치환 · ⓑ SSOT 폐기 ·
   ⓒ ci/guards 이동 · ⓓ 유지) · 만료 조건 · 어느 단계 파일에 넣었는지(`step 파일` 열)까지.
   행 없는 가드는 다음 사람이 지울 근거가 없어 영원히 남는다.

## 새 검사를 어디에 넣나

- **스크립트 동작**이면 `scripts/tests/<sut>.test.sh` 격자다 — `ci/` 가 아니다.
- **문서·스크립트가 옛 형태로 되돌아가는 것**을 막는 부정 grep 이면 `ci/guards/` 의
  기존 주제 파일(`prose-regression.sh` · `single-definition.sh` …)에 항목을 더한다.
- 어느 쪽도 아닌 **기계 계약**(런타임 치환 슬롯 · 라벨 이름 · 전이 동사 · 코멘트 마커)
  이면 주제가 맞는 단계 파일에 블록을 더한다. 맞는 단계가 없으면 새 `NN-<이름>.sh` 를
  만들고 위 두 리터럴의 `M` 과 이 문서의 표를 고친다.

## 손으로 돌릴 때

`bin/ci` 를 직접 실행하지 마라 — 박스 전역 직렬 큐(`scripts/ci-queue.sh`)가 진입점이다
(README `bin/ci` 절 참조). 한 단계만 보고 싶으면 그 파일만 돌린다:

```sh
bash ci/steps/85-loop-status.sh
```
