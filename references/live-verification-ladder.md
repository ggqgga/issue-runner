### 검증 사다리 — 실측이 필요할 때 어디까지 올라가나

루프(issue-runner · verify-runner · closeout · deploy-cycle)가 "라이브 검증이 필요하다"
는 이유로 **시도 없이 멈추는 것을 금지**하는 문서다. 실측 필요는 멈출 이유가 아니라 다음
할 일이다. 아래 네 칸을 ①→②→③ 순으로 올라가고, **시도한 칸과 실패 출력을 인용**해야만
④(사람)로 넘길 수 있다.

## 칸별 상세

### ① dev 서버

서버 로직·화면·DB 상태처럼 워커 없이 판정 가능한 것은 전부 여기서 끝난다. 실장비가
필요하다고 적힌 항목도 절반은 여기서 재현된다 — 먼저 시도하라.

**①a 와 ①b 는 DB 가 다르다.** 미니(루프 박스)의 워크트리는 픽스처·시드 수준의 빈 DB 라
운영 데이터가 있어야 보이는 화면·상태 전이와 쓰기 왕복을 판정하지 못한다. 그런 항목은
"dev 에서 못 밟음"으로 넘기지 말고 ①b 로 간다 — BoDAT 은 운영 DB 덤프를 띄운 dev 서버가 m2
에 있고, 거기서는 **쓰기까지** 테스트한 뒤 재덤프로 지운다(BoDAT `Plans/dev-isolation.md`
E장·결정 12). 다른 레포에는 ①b 가 없다.

**①b 에 올라오는 루프 주체는 verify-runner·closeout 둘뿐이다.** 구현 워커(issue-runner 가 디스패치)는
①a 에서 멈추고 ①b 로만 밟히는 줄을 PR test plan 에 열린 채 둔다 — 워커는 동시에 여러 개가 돌아 m2 잠금
하나를 두고 다투고, 직렬로 도는 verify-runner 가 같은 줄을 PR head 로 밟는다(사용자 결정 2026-10-27,
`references/loop-conventions.md` §9). 그 줄은 사다리 실패가 아니므로 `BLOCKED:`·`hold:ladder` 근거가 아니다.

**①b 절차 (BoDAT, 미니·맥북 어디서든 `ssh ggq-m2`).** m2 의 ruby 는 mise 라 원격 명령 앞에
`export PATH="$HOME/.local/share/mise/shims:$HOME/.local/bin:/opt/homebrew/bin:$PATH"; cd ~/Projects/BODA/BoDAT &&`
를 붙인다.

1. **잠금 확인** — `script/dev-checkout --status` 의 출력이 정확히 `잠금 없음` 이어야 한다.
   ⚠️ 이 명령은 **잠겨 있어도 exit 0** 이다 — `&&` 로 다음 명령을 잇지 말고 출력을 비교하라
   (2026-10-27 실측: `&&` 로 이어 남의 잠금 밑에서 dev DB 를 썼다). 잠겨 있으면 남의 잠금을 풀지
   않는다 — ①b 실패로 인용(`--status` 출력)하고 그 항목은 넘긴다. **잠금 시각 + 이 주체의 상한(15분)이
   07:05~08:00 에 걸리면 잡지 않는다**(m2 deploy-cycle ② 가 07:25 에 덤프한다 — 07:00 에 잡아 15분을 쓰면 그
   회차를 막는다).
   **오래된 잠금** — `--status` 의 보유자·시각을 보고 같은 보유자가 **2시간 넘게** 쥐고 있으면 풀지 말고
   그 틱 Report 에 `BLOCKED: m2 dev 잠금 장기 보유 <보유자> <시각>` 한 줄을 올린다(죽은 주체가 남긴 잠금이면
   모든 ①b 가 "잠김"으로 조용히 넘어가 영영 안 밟힌다).
2. **띄우기** — `script/dev-checkout <브랜치> --owner <주체>`(주체 = `verify-runner`·`closeout`·`e2e-test`
   등 — 구현 워커는 ①b 에 오지 않는다). 브랜치는 **origin 에 push 돼 있어야** 한다(`origin/<브랜치>` 를 체크아웃한다).
   머지 뒤라면 `main`. 이 명령이 bundle·migrate·재기동·`/up` 확인까지 한다.
   **exit 0 이고 마지막 줄이 `ok  dev 서버가 <브랜치>(…)로 떴습니다` 일 때만 3단계로 간다.** 비0 이면 밟지 않는다:
   exit 2(그 사이 누가 잠금)는 1단계 "잠겨 있으면" 과 같게 인용하고 넘긴다. 전환 뒤 실패(`전환 뒤 실패 — 잠금을
   유지합니다`)는 잠금이 **내 이름으로 남은** 상태다 — `--release --owner <주체>` 로 한 번 복구를 시도하고, 그것도
   실패하면 Report 에 `BLOCKED: m2 dev 전환 실패 — 잠금 <주체> 유지` 를 올린다(잠금을 쥔 채 두는 것이 남의 쓰기를
   막는 안전한 쪽이다).
3. **밟기** — 서버 값·쓰기는 `bin/rails runner`, 화면·요청은 `curl http://192.168.0.11:3000/…`
   (미니·m2 LAN). 쓰기는 왕복(쓰기 → DB·화면 반영 → 되돌리기 또는 다음 상태)까지. AdsPower 쓰기는
   `zdev_` 그룹 안에서만 나간다(dev 서버 가드가 밖을 거부한다). **Instagram·Threads 공개 쓰기는
   ①b 에서도 하지 않는다**(③ 의 공개 쓰기 규칙 그대로). `.env`·토큰·덤프 데이터를 코멘트·로그에
   옮기지 않는다.
4. **풀고 재덤프** — `script/dev-checkout --release --owner <주체>` 뒤, **지체 없이** 한 명령으로:
   `[ "$(script/dev-checkout --status)" = "잠금 없음" ] && script/dev stop && script/dev-sync-db && git checkout -- db/schema.rb && BIND=0.0.0.0 script/dev start && curl -fsS -o /dev/null http://127.0.0.1:3000/up`.
   ①b 를 밟았으면 **읽기만 했어도 생략하지 않는다** — runner 의 부수 쓰기(캐시·touch)와 브랜치 마이그레이션이
   남는다. **재덤프까지가 테스트다**(흔적을 남기면 다음 검증이 그 데이터를 운영 상태로 오독한다).
   **이 줄이 어디서든 비0 이면 PR 코멘트로 끝내지 않는다** — 그 틱 Report 에
   `BLOCKED: m2 dev 재덤프 실패 — <단계> rc=<n> · dev DB 더러움 · 서버 <켜짐|꺼짐>` 한 줄을 올린다(서버 상태는
   `curl /up` 로 잰다). 잠금은 이미 풀려 있어 다음 주체가 `잠금 없음` 만 보고 더러운 DB 위에서 판정한다 — 사람
   눈에 닿는 곳은 Report 다. `dev-sync-db` 가 DB 를 바꾼 뒤(`db:migrate`·`dev-isolate`) 실패하면 덤프로 따라온
   열린 AdsPower 명령이 안 닫혔을 수 있어 특히 그렇다.
   ⚠️ **알려진 틈(BoDAT #6772).** `--release` 가 잠금을 푼 뒤 `dev-sync-db` 가 다시 잡기까지 잠금 없는
   순간이 있다 — 그 사이 다른 주체가 잠그면 `script/dev stop` 이 **그 주체의 서버를 내린다.** 앞의
   `--status` 재확인은 그 창을 좁힐 뿐 닫지 못한다. 잠금을 쥔 채 stop·재덤프·기동을 하는 명령은 #6772
   몫이고, 들어오면 이 4단계를 그 한 줄로 바꾼다. 그 전까지: 재확인이 `잠금 없음` 이 아니면 재덤프를
   **하지 않고** 보유자를 인용해 보고한다(dev 가 더러운 채라는 사실도 함께). `dev-sync-db` 가 exit 3
   이면 그 사이 누가 잠근 것이다 — `--status` 를 인용하고, 그 주체의 서버가 내려갔는지
   (`curl -fsS http://127.0.0.1:3000/up`) 확인해 보고한다. 내려갔으면 그 주체에게 알리는 것까지가 이
   주체의 몫이다(남의 잠금 밑에서 `script/dev start` 로 되살리지 않는다).
5. **기록** — 근거 줄 앞에 수단 `[m2 dev]` 를 적는다. m2 에서 본 것을 프로덕션 관측으로 바꿔 적지
   않는다.

한 틱에 잠금은 **한 번**만 잡고, 그 안에서 여러 항목을 밟은 뒤 재덤프는 마지막에 한 번 한다.

**화면을 프로덕션에서 봐야 할 때 — 주소를 먼저 의심하라.** 크롬이
`ERR_ADDRESS_UNREACHABLE` 인데 같은 호스트를 `curl` 은 200 으로 받으면, 서버가 죽은 게
아니라 **그 주소만 크롬에서 안 열리는 것**이다(2026-09-10 BoDAT 개발 맥북의 Chrome 실측 —
다른 박스에서 같은 결과라는 보장은 없다: 미니의 LAN 주소
`192.168.0.91:3000`·mDNS 이름 `bodat.local:3000` 은 크롬에서만 막히고, 같은 박스의
Tailscale 주소 `100.65.53.51:3000` 과 루프백은 정상. 같은 크롬이 공유기 `192.168.0.1` 은
연다 — LAN 차단도, DNS 도, macOS 로컬 네트워크 권한도 아니다).

그러니 "브라우저로 프로덕션을 못 봤다"를 **칸 실패로 적지 마라.** 순서는 ① 그 레포의
원격 접근용 주소(BoDAT 은 테일넷 IP) ② SSH 터널. 루프백은 이 차단과 무관하다.

⚠️ **터널은 성공을 확인하고 써라.** 고정 포트는 이미 그 포트를 쓰는 dev 서버·다른 터널을
프로덕션으로 오판하게 만든다(거짓 초록). 포트를 매번 뽑고, 포워딩 실패 시 ssh 가 죽게 하고,
열자마자 찔러 본다:

**레시피는 여기 베끼지 않는다 — 단일 출처는
`skills/closeout/references/smoke-prompt.md` 의 터널 절이다.** 포트 충돌 재시도(바인드 실패는
도달 불가가 아니다) · control socket 범위 정리(`pkill` 은 남의 터널을 끊는다) · 프로브 데드라인
(`--connect-timeout 3 --max-time 10`) · **스모크가 끝난 뒤에 정리**(프로브 직후에 끊으면 정작
볼 화면을 못 본다)까지 그 절차를 그대로 따른다. 사본을 두면 한쪽만 고쳐져 갈라진다.
`<호스트별칭>`·`<원격포트>` 는 그 레포 배포 문서에서 찾고, 못 찾으면 지어내지 말고 그 사실을
적는다. 배경·실측 표(그 맥북의 Chrome 기준)는 BoDAT `hotfix` 5절(옛 `deploy-bodat`).

### ② 워커 런타임 — 실장비 없이

`bin/dry-run` 은 claim 과 무관하게 레시피/블록을 직접 실행한다. 서버의 claim 게이트·
인플라이트 상태를 타지 않으므로 워커 큐가 막혀 있어도 돈다. AdsPower Local API 호출이
필요하면 미니 경유 릴레이(포트 50325)로 닿는다.

한계: dev 에서는 "AdsPower 에 실제로 도달했는가" 를 판정할 수 없다. 도달 자체가 판정
대상이면 ③ 으로 올라간다.

### ③ TEST 워커 — 실장비

- **루프 세션은 미니(Mac mini, 호스트 `bodat-mini`)에서 돈다.** 미니에서 TEST 워커는
  `ssh test '<cmd>'` 로 **직결**된다(호스트명 `DESKTOP-O3BOREC`). 맥북 세션에서는
  `ssh bodat-mini 'ssh test <cmd>'` 중첩으로 같은 곳에 닿는다.
- 한글이 섞이거나 인용이 중첩되는 PowerShell 은 미니 헬퍼 `~/bin/wexec` 로 넘긴다
  (셸 인용 깨짐을 피한다).
- **워커는 Windows 이고 SSH 로 들어간 콘솔은 세션 0 이라 창을 못 본다.** 화면 판정이
  필요하면 워커 데스크톱 캡처를 쓴다 — `BoDAT-Worker` 작업의 principal 을 복제한
  `schtasks /xml` 작업으로 콘솔 세션에서 실행해야 창이 보인다.
- 레시피 테스트런: `aging_recipes` 행을 `test_claim` 으로 지정 워커/프로필에서 돌린다.
  프로필은 **#18** 이 기본이다 — **#20 은 맥 드라이런 에이전트 몫이라 워커에서 열면
  AdsPower 계정이 잠긴다.**
- `test_claim` 의 게이트는 **대상 집합만** 센다(옛 전역 인플라이트 라이브락 #2640 은 고쳐졌다 —
  프로필 지정이면 그 프로필이 진행 중일 때만 안 열린다). 그래도 안 걸리면 그것으로 칸 ③ 이 실패한
  게 아니다 — **`bin/dry-run` 으로 우회**해 같은 워커에서 다시 시도한다.
- **무장 칸은 레시피 번호 `test_recipe_id` 다.** 옛 이름 칸 `test_behavior` 는 `ChannelConfig.sanitize`
  가 조용히 버려, 넣으면 이전에 남은 레시피가 돈다(2026-10-27 실측). 무장 뒤 그 칸을 다시 읽어 확인한다.
- **dev 워커(`zdev_` 그룹)는 m2 dev 를 폴링한다** — 그 워커로 재현할 항목은 무장도 m2 dev DB 에
  한다(①b 잠금 안에서 — 그래서 구현 워커는 이 경로를 쓰지 않는다). 운영 TEST 워커는 prod DB 에 무장한다.
- **무장했으면 복원은 필수다.** 테스트를 위해 켠 스위치(test_mode·레시피 배정·작전
  무장)는 판정이 끝나는 즉시 원상 복구한다.
- **공개 쓰기(댓글·팔로우)는 우리 계정에만.** 도달 대상·고객 게시물에 검증 흔적을
  남기지 마라.

### ④ 사람

①②③ 을 전부 시도해 전부 실패했을 때만 도달한다.

## 규칙 — 미루는 방법

- **미루려면 시도한 칸과 실패 출력을 인용한다.** 인용은 명령 한 줄과 그 출력의 마지막
  20줄이다. "실장비가 필요하다"·"배포 후 확인" 같은 서술은 인용이 아니다.
- **`needs:hardware` 라벨만으로는 미룰 수 없다.** 그 라벨은 "실장비가 관련된다" 는
  분류일 뿐 시도 면제가 아니다.
- 사다리 끝까지 실패했을 때만 `needs-human` + `hold:ladder` 로 남긴다:
  `$SCRIPTS/transition.sh <전이> <repo> <issue|-> <pr> --reason ladder`.
  `--reason ladder` 는 **칸을 실제로 올라가 인용을 남긴 경우에만** 쓴다. conflict 도
  아니고 인용도 없으면 그건 `policy` 다.
- 칸 ①②③ 중 어디서든 판정이 서면 사다리는 거기서 끝난다. 위 칸을 "혹시 몰라" 더
  올라가지 마라.

## 스킬이 없어도 명령은 그대로

`worker-ssh` · `worker-recipe-test` 스킬은 개인 디렉터리(`~/.claude/skills/`, 레포 밖)에
있어 **미니의 루프 세션엔 없을 수 있다**(복사 설치 — README 설치 절 참조). 스킬이
없어도 이 문서의 명령은 그대로 친다 — 통로는 `ssh test` 직결이지 스킬이 아니다.
